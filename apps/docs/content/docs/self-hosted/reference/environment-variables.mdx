---
title: Environment variables
description: Every variable the apps read, which app reads it, and what it does.
---

Each app reads its own `.env.local`: `apps/web`, `apps/business`, `apps/admin` and
`apps/support-bot`. Scripts run from the repository root (`packages/db`, `packages/demo`,
`apps/invoice-job`) read the root `.env.local`. Every location has a commented `.env.example` to
copy from.

**Apps:** W = guest site, B = host dashboard, A = admin console, S = support bot,
I = invoice job, R = root scripts.

| `PG_IDLE_TX_TIMEOUT_MS` | all | no | Idle-in-transaction limit. Default `15000`; the invoice job uses `300000`. |

### Admin console database roles

To look at production from the admin console without the apps' full-access `DATABASE_URL`,
give it the two roles migration `0054_admin_roles.sql` creates. `ob_admin_read` may only read
what the pages show; `ob_admin_write` may only make the changes the admin actions make (booking
lifecycle, refunds, forced edits, resolving a flagged payment). Neither can change the schema
or read password hashes, tokens or 2FA secrets. Both bypass row-level security: staff see every
host's bookings.

The roles cannot log in. Once `0054` is applied, create one login user for each in the Neon SQL
editor, as `neondb_owner`. Use SQL, not the Neon console: a role made in the console is added
to `neon_superuser`, which defeats the point.

```sql
CREATE ROLE admin_reader LOGIN PASSWORD '<long random password>' IN ROLE ob_admin_read;
ALTER ROLE admin_reader SET role = 'ob_admin_read';

-- Only if the console should be able to act, not just look:
CREATE ROLE admin_writer LOGIN PASSWORD '<another long random password>' IN ROLE ob_admin_write;
ALTER ROLE admin_writer SET role = 'ob_admin_write';
```

`SET role` makes each session act as the role itself. Membership alone is not enough:
`BYPASSRLS` is never inherited, so without it row-level-secured tables such as `bookings` would
look empty.

Put the connection strings (same host and database as `DATABASE_URL`, `?sslmode=require`) in
`apps/admin/.env.local` as `ADMIN_DATABASE_URL_READ` and `ADMIN_DATABASE_URL_WRITE`, and remove
the production `DATABASE_URL` from it. The red banner shows where each connection goes. To check
a login, connect with it and run `SELECT current_user;` (expect `ob_admin_read`) and
`INSERT INTO audit_log (action) VALUES ('probe');` (expect `permission denied`). The invoice job
needs full access, so the console refuses to run it while these are set. To revoke access, `DROP
ROLE admin_reader;` (or `admin_writer`).

| `CHATWOOT_BUSINESS_INBOX_ID` / `CHATWOOT_ACCOUNT_WEBHOOK_SECRET` / `BUSINESS_APP_URL` | with host support | The host-support inbox. With email tracking, `BUSINESS_APP_URL` must equal `NEXT_PUBLIC_BUSINESS_URL`, or the links in support replies are not tracked. |

`CHATWOOT_BUSINESS_INBOX_IDENTIFIER` and `CHATWOOT_BUSINESS_INBOX_HMAC_TOKEN`.
